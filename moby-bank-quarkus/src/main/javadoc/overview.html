The Quarkus backend of the Moby Bank agent harness: the API a chat UI uses to talk to an agent that runs in a Docker Sandbox, locally or in the cloud, with sessions that can move between the two.

How the code is organised

Four layers, and dependencies point one way: interfaces.rest → application → domain ← infrastructure. The domain depends on nothing; infrastructure implements the domain's ports. Tests fail the build if a layer imports something it should not.

Layers
PackageRole
{@link com.mobybank.harness.domain}Aggregates, value objects, events, and the ports.
{@link com.mobybank.harness.application}The use cases, with commands and DTOs at the edge.
{@link com.mobybank.harness.infrastructure}In-memory state, the fakes, and the choice of adapters.
{@link com.mobybank.harness.infrastructure.sbx}Real sandboxes through the sbx CLI.
{@link com.mobybank.harness.infrastructure.graph}OneDrive through Microsoft Graph.
{@link com.mobybank.harness.interfaces.rest}The HTTP and server-sent-events API.
